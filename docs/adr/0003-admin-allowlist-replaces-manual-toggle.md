# Organizer mode: name allowlist on Tysons Corner, unrestricted manual toggle stays on Austin

`adminMode.ts` documents itself as a manual, reversible, self-serve switch in More — anyone can flip it on or off, and it explicitly disclaims being a security boundary. That behavior is unchanged for Austin: every viewer there can still flip the toggle themselves, exactly as today, so the existing full-roster preview experience keeps working for anyone poking around that conference.

For the Tysons Corner conference specifically, we're replacing that manual switch with automatic activation: if the name entered at check-in matches a hardcoded first+last name pair on an allowlist, Organizer mode turns on for that session with no toggle at all — not to turn on, and not to turn back off. Which behavior applies is keyed off the active conference, not a single global rule.

This is worth recording because it looks like a regression at a glance (the toggle a future reader expects, per the existing code and its own comments, is simply gone for ~50-60 Tysons attendees) when it's actually a deliberate, conference-scoped simplification: the presenter doesn't want to hand out admin access by word-of-mouth ("go flip the switch in More") for a room of strangers, but Austin has no such audience-control concern, so its original unrestricted toggle is left alone. The trade-off accepted for Tysons: no way to spot-check the plain-attendee view from an admin's own checked-in identity, and no stronger guarantee against name-spoofing than typing someone else's name at check-in — acceptable because, like the toggle it replaces, this is explicitly a demo affordance, not a security boundary.
